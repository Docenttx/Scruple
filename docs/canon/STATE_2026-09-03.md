# Where Scruple stands — 2026-09-03

_Written at the end of the 2026-09-02/03 overnight. Supersedes the status
sections of `demo-readiness/*` and `RUNTIME-INTEGRITY-WORK-ORDERS.md`._

## The one-paragraph version

Every generation flow now produces provenance **and** an output, verified by
side effect rather than by report: 16 leaves, five hashes each, witnessed,
present on the witness server, artifact bytes re-hashed on disk and matching.
The last untested flow — Kohya through the capture component — ran against a
real trainer on real hardware for the first time. Two live security defects
were found and closed. Three preimages that no outsider could recompute now
recompute in Python. What remains is mostly parked on purpose, plus five
things that are genuinely the founder's to decide.

### Security — both live, both closed

- **`web_run` had no authentication.** `POST https://aquanomous--run.modal.run`
  answered the open internet with HTTP 200; a well-formed body ran an arbitrary
  ComfyUI graph on our GPU with the models volume mounted. Every `admin-*`
  sibling checked a token; the one that *spends* did not.
- **`localPath` read any file on the host.** The comment claimed a traversal
  guard; the guard was `path.resolve()`, which normalises and does not confine.
  An exfiltration primitive rather than a read, because the bytes are hashed,
  stored content-addressed, and served back by `/api/artifact/<hash>`.

### Correctness — the pattern behind almost all of it

**A measurement fails, the failure is caught, the run continues, and the leaf
records a weaker claim while the caller is told `ok`.** WO-27 settled that once
for `input_hash` and the rule was applied in exactly one place. Migrations
049/050/051 and the `jcs-2` profile are that rule applied where it was not:

- `input_hash` and `model_fingerprints_hash` are reproducible cross-language
  (**proven**: Python recomputed `input_hash` from the stored row and matched);
- `machine_manifest_hash` records **which** of three documents answered;
- fingerprints have three states, not two — `unavailable` ≠ `none`;
- `witnessed` requires a signature, not merely a non-null response body;
- degraded runs are visible to callers (`storage: LOCAL ONLY` was true of every
  run tonight and nothing could see it);
- a `run_sequence` is reserved by a **row**, so a race cannot leave an orphan
  leaf on an append-only log.

## What is left

### Tier 2 — four items, none of them large

These are real and unfixed. They were outranked, not dismissed.

- **WO-68** — `container_manifest.py:84` folds a transient error class name
  into the directory digest under a comment claiming it "keeps the hash
  deterministic". It does the opposite: a permission blip changes the manifest
  hash of an unchanged container. Collect unreadable paths into a list and mark
  the manifest incomplete.
- **WO-72** — `projectName` is sent to the witness on every leaf and is
  mutable and unpersisted. Rename a project and historical leaves stop
  verifying.
- **WO-73** — the v1 fallback sets `leaf_hash = output_hash` with no domain
  separation, so two iterations with identical output bytes get identical leaf
  hashes and the chain is ambiguous.
- **WO-75** — the model fingerprint cache keys on `(path, mtime_ns, size)`, so
  a file modified and `os.utime`'d back evades re-fingerprinting on a warm
  container.

### Tier 3 — parked deliberately

Correct, and triggered only by load, concurrency or scale that Studio does not
have: `pollRunJob` idempotency, transient-502-becomes-terminal, the timeout
ladder, the 48-bit storage path prefix, the `CanonicalizationError` re-upload
loop, `outputKind` precedence on the async path, and the base64/streaming
optimizations. Revisit if Studio ever takes traffic.

### Host — one that matters and three that are tidy-ups

- **`scruple.stooges.ai` is an unsupervised `next dev` process on :3001.** Not
  in systemd, not in pm2, will not survive a reboot, and it was *down* when
  this session began. Editing the repo edits the live site with no build step.
  This is the largest operational fragility on the box.
- `/data` at 93%; `ravend-mainnet` enabled and crash-looping past 61,000
  restarts (testnet, the live anchor, is healthy); nginx carries a dead
  `canvas.scruple.ai` vhost.

### Founder decisions — five, and none of them are chores

1. **Which certificate signs.** The signer falls back to a development cert, so
   credentials validate `Valid` with `signingCredential.untrusted`. Fine for
   Studio, which has no users. **Not fine for Stooges, which has customers.**
   See `STOOGES_C2PA_WATERMARK_ONLY.md`.
2. **WO-35: custom image or boot-time fetch.** Both work; the trade is that the
   Docker-free path makes "only these trees are present" a property of a boot
   script rather than an image digest, which weakens `build_measurement`. This
   is the certification argument, so it is yours.
3. **Canvas `sealed`.** Blocked by two things: CSB-01, a *designed* refusal (no
   admissible probe exists from canvas's tenant position), and the absence of
   `SCRUPLE_BUILD_REGISTRY_KEY_HEX` — minting which creates the registry's root
   signing identity and should not happen as a side effect of moving a status
   field. The manifest is built and measures to
   `sha256:cb9a5980…`; §5 of `STUDIO_SEAL.md` claims `verifying` while the fold
   says `integrating`, because recording it needs that key.
4. **The MCC package.** F-01's three wrong hashes and F-04's one are corrected
   in place; the model itself was recovered from the Drive substrate. Never
   transmitted, so nothing needs re-issuing — but §4 promises an auditor
   "holding only the model and its sidecar", and any package that ships must
   include the model.
5. **Putting scruple-web under supervision.**

## The habit that found most of it

Nothing on this page was found by reading code. `web_run` was found by sending
an unauthenticated POST; the CPU-pod defect by reading a boot report that
disproved my own diagnosis; the cross-language divergence by printing both
languages' bytes side by side. Two of my own fixes were wrong on the first
attempt and the evidence said so — a comment in `argv.ts` that blamed the
interpreter, and a `run_sequence` "reservation" that reserved nothing while
claiming to.

**Verify by side effect, not by report** — including your own.
