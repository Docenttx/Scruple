# Session: 2026-06-21 — Sign-in unblock + ComfyUI venv migration + canvas/Modal node parity

## What happened (chronological)

### 1. Sign-in stuck for new dev account
User reported `scruple.stooges.ai` sign-in "wasn't working". Server log showed two compounding issues:
- `_migrations` table only recorded through `015_run_jobs.sql`, but `iterations` schema already had `workflow_hash` / `leaf_scheme` / `model_fingerprints` (016/017/018 had been applied physically but never recorded). Every request re-ran the migration runner and crashed with `duplicate column name: workflow_hash`. Caught + logged, didn't kill auth, but produced loud noise.
- The actual sign-in failure was a `403 AccessDenied` from `lib/auth/auth.ts`'s `signIn` callback. Email gate (`SCRUPLE_ALLOWED_EMAILS` in `.env.local`) didn't include the new account.

Fix:
- Backfilled `_migrations` with 016/017/018 rows (schema already at v018).
- Added `shaun.hargadine.ge@gmail.com` to `SCRUPLE_ALLOWED_EMAILS`.
- Restarted dev server with fresh `.next` cache.

Also added a temporary diagnostic wrapper to the `[...nextauth]/route.ts` that captured the actual OAuth callback's `Set-Cookie` to `/tmp/scruple-auth-diag.log` (proved Auth.js was emitting `__Secure-authjs.session-token=…; HttpOnly; Secure; SameSite=Lax` correctly — confirmed server-side healthy). Wrapper removed once verified.

### 2. ComfyUI restart-after-node-install hygiene
User flagged: "ComfyUI seems to have a hard time restarting after node installs." Investigation found:
- Service ran `/usr/bin/python3` (system) with no venv. `ubuntu` can't write to system site-packages.
- ComfyUI-Manager's auto-`uv pip install` for missing custom-node deps (`comfyui-frontend-package==1.42.8`, `diffusers` for seedvr2 and easy-use) failed silently on every restart for lack of root.
- `comfyui-easy-use` import time was 10.7s — Manager retrying installs each startup.

Fix (proper venv migration):
- Created `/data/reference/ui-inspire/ComfyUI/.venv` with Python 3.10, pip, uv.
- Installed torch CPU + all `requirements.txt` + every custom-node's `requirements.txt` via uv pip (one resolution pass).
- Updated `/etc/systemd/system/comfyui.service` ExecStart to `.venv/bin/python3`. `.bak` kept.
- `systemctl daemon-reload && systemctl restart comfyui.service`.

Result: 0 install failures per restart, `comfyui-easy-use` import 10.7s → 0.2s, service up in <8s.

Recorded as `memory/reference_comfyui_layout.md`.

### 3. seedvr2 IMPORT FAILED (still cosmetic after venv migration)
Even with deps satisfied, `seedvr2_videoupscaler/src/interfaces/dit_model_loader.py` and `vae_model_loader.py` crash at `define_schema()`:
```python
devices = get_device_list()   # [] on CPU-only
...
default=devices[0],            # IndexError
```
Initially I told user this was cosmetic ("Modal has CUDA, you don't need this node locally"). User pushed back: **"we just want our users to have seamless, painless canvas work."** Correct — if the canvas can't show seedvr2, users can't add it to a workflow, and the existence of Modal's GPU runner doesn't matter.

That kicked off WO `docs/wo/2026-06-21-canvas-node-parity.md`. See that doc for the full plan, audit, and morning briefing.

### 4. Canvas/Modal node-set parity (the overnight work)

Executed CV-1..7. Highlights:

- **CV-2 audit**: Only `seedvr2_videoupscaler` has registration-time GPU bugs (two `define_schema()` classmethods). Every other custom node either checks `torch.cuda.is_available()` or only touches GPU at exec time. Small initial blast radius, but the fork pattern set up tonight generalizes to every future GPU-only node.
- **CV-3 shim**: built `scruple_nodes/_compat.py`. First version looked up modules by dotted name — failed, because ComfyUI's `load_custom_node` keys `sys.modules` by absolute path string (per `sys_module_name = module_path.replace(".", "_x_")` in `nodes.py:2208-2214`). Rewrote to find modules by `__file__` suffix. Also discovered ComfyUI iterates `custom_nodes/` via `os.listdir` (filesystem-arbitrary), not alphabetical — so `scruple_nodes` isn't guaranteed to load before any patch target. Shim demoted to "belt-and-braces" layer.
- **CV-4 verify**: `/object_info` 919 → 922 (+3 SeedVR2 nodes that previously failed to register). All 4 SeedVR2 types visible. 0 IMPORT FAILED, 0 installed failed.
- **CV-5 Modal parity audit (surprise)**: Modal image has **only ComfyUI-Easy-Use**; on-host canvas has 6 packs. Three (VideoHelperSuite, seedvr2, scruple_nodes) are real runtime dependencies absent from Modal. The "design on canvas → Queue → Modal 400s on unknown node" failure mode is already latent today, just nobody's noticed.
- **CV-6 fork structure**: vendored seedvr2 to `external/scruple-nodes/seedvr2_videoupscaler/` with `upstream-vendored` + `scruple-canvas-fork` branches. In-place `custom_nodes/seedvr2_videoupscaler` is now a symlink to the fork. Original moved to `external/scruple-nodes/_upstream-snapshots/seedvr2_videoupscaler-2026-06-21/`. Added `README.md` + `sync-upstream.sh`.
- **CV-7 memory**: `reference_canvas_node_fork_pattern.md` written; `MEMORY.md` pointer added.
