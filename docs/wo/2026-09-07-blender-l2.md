# WO series — Scruple for Blender to the L2 floor

_2026-09-07. Overnight, detached. Target: take the Blender addon as far as it
can go without a human at a GUI._

## Why this series exists

`/data/scruple-blender` shipped a working shell on 2026-07-17: 81 tests green,
an installable zip, auth, capture, handlers, paid operators and an N-panel. It
was built against the **v1** surface and it has not moved since.

Three things are now true that were not true then:

1. **There is an SDK.** `packages/scruple-host-sdk/` is the skeleton a vendor
   implements against — `auth`, `capture`, `witness_flow`, `queue`, `envelope`,
   `capabilities`, `ratchet`, `manifest`, `state`, `http`. The addon predates
   it and carries its own hand-rolled copy of nearly every one of those in
   `lib/`. Two implementations of the same contract will diverge, and the
   addon's is the one nobody is testing against the server.
2. **There is a v2/L2 surface.** The addon calls `/api/lock/*`,
   `/api/witness/cad`, `/api/projects`, `/api/stripe/*` — **not one** of the
   sixteen `/api/v2/*` routes. It cannot produce a signed leaf, cannot fetch a
   receipt, cannot be independently verified, and knows nothing about
   canonicalization profiles or measurement honesty.
3. **The floor binds the client.** `L2_AS_THE_VENDOR_FLOOR.md` settles founder
   question 2: **client-binding, H-4 mandatory.** The addon *is* the client.
   Store-and-forward (`queue.py`) is listed there as a floor item that "exists
   and is unwired" — in the addon it is hand-rolled as `lib/queue_store.py`
   and never reconciles.

## Ground rules for every WO in this series

- **Where output goes.** Reports and machine-readable artefacts land in the
  **addon** repo at `/data/scruple-blender/docs/canon/blender-l2/`, committed
  with the code they describe. WO-B1 established this; follow it. (The original
  wording of WO-B1 said only "`docs/canon/blender-l2/`" without naming a repo —
  the addon is the right home, since the work is the addon's.)

- 🔴 **Never contact `127.0.0.1:5799`.** That is the production witness and a
  live audit log; a run on 2026-08-29 wrote 9 real rows into it. Use
  `$WITNESS_SERVER_URL`, which the runner points at a scratch witness on 5899.
- 🔴 **Never contact `:3001`.** That is `scruple.stooges.ai`, live and
  unsupervised. The runner starts a scratch app on `:3902` with its own DB.
- Signing targets the **CVM surrogate** on `127.0.0.1:8799`. The real Signer
  CVM stays down. The surrogate reports `protectionMode: SOFTWARE` truthfully —
  never record a leaf as hardware-backed because it signed.
- **Verify by side effect, not by report.** A test that cannot fail proves
  nothing. Every gate below names an observable the WO must produce and a
  control that must *not* appear.
- Blender **3.0.1 is installed** at `/usr/bin/blender` and renders headless
  (verified: Cycles CPU, 160×120, 4 samples → real PNG + real `.blend`). Use
  real content. Do not simulate what you can generate.
- Commit each WO's work in `/data/scruple-blender` (local git). Do not push.

## WO-B1 — The gap, measured

Inventory the distance between the addon and the floor. No fixes.

Produce `docs/canon/blender-l2/01-GAP.md` **and** a machine-readable
`gap.json` in the same directory, with three tables:

1. Every endpoint the addon calls → its v2 replacement, or "no equivalent".
2. Every module in `scruple_blender/lib/` → the `scruple_host_sdk` module that
   supersedes it → whether behaviour differs (quote both where it does).
3. Every L2 floor item in `docs/canon/L2_FLOOR.md` and
   `L2_AS_THE_VENDOR_FLOOR.md` → what the addon does about it today.

**Gate:** `gap.json` parses; every row cites `file:line`; the existing suite is
run and its result recorded as the baseline (expected: 81 passing). State the
count you actually observed — if it is not 81, that is the finding.

## WO-B2 — The addon consumes the SDK

Replace the hand-rolled `lib/` with `scruple_host_sdk`, keeping only what is
genuinely Blender-specific (bpy handlers, operators, panels, preferences).

A Blender addon cannot `pip install`, so the SDK must be **vendored** into the
zip at build time by `build/build_addon.sh`, with the source commit recorded so
a vendored copy can be traced back.

**Gate:** the baseline suite still passes; a new test asserts the SDK module is
the one actually imported at runtime (not the old `lib` twin); and the old
duplicate modules are **deleted**, not left orphaned. Control: a test that
fails if both implementations are importable.

## WO-B3 — The v2 witness path, at L2

Move capture onto the v2 surface: witness through `/api/v2/witness`, keep
`leaf_signature` / `leaf_signer_key_id` / `leaf_signature_alg`, record the
`canonicalization_profile`, carry the three measurement-honesty states rather
than asserting success, fetch receipts from `/api/v2/receipt/[leaf_id]` and
verify through `/api/v2/verify/[content_hash]`.

**Gate:** a leaf produced from a **real headless Blender render** appears in
the scratch witness; its `content_hash` re-hashes from the PNG on disk and
matches; `/api/v2/verify` reports it independently verifiable. Control: a leaf
whose bytes are altered by one pixel must FAIL verification — show both.

## WO-B4 — Store-and-forward, and gap detection

Wire the SDK queue so capture survives the server being unreachable, and add
the reconciliation the floor calls for: at settlement, a missing leaf is
**detected**, not silently absent.

**Gate:** stop the scratch witness, capture three events, restart it, and show
all three land. Then deliberately drop one from the queue and show the
reconciliation reports the gap. A reconciliation that reports "all clear" on
the dropped case fails this WO.

## WO-B5 — The dashboard

The panel today is a sign-in gate, a project header, four paid buttons and a
receipt list. It is not what Studio and the Fusion palette are. Build the
Blender UI to match them as **project manager, tracker, and lock/mint
dashboard**: project list and switching, per-session capture tracker with each
item's state, lock/mint controls with price and current state, queue and
offline indicator, assurance tier shown honestly (verified vs passthrough),
receipt drill-down, and the error surface.

Read `app/embed/fusion/FusionPalette.tsx` (868 lines) for the feature surface
to match. Blender's UI is `bpy` layout code, not React — match the
**functionality and information architecture**, not the markup.

**Gate:** mock-bpy tests that assert each region renders in each state —
signed-out, signed-in-no-payment, queued-offline, verified, passthrough,
error. Control: a test asserting a region is ABSENT when its state does not
apply, so a panel that always draws everything cannot pass.

## WO-B6 — Real content, end to end

Drive the whole flow on generated Blender content: render and save headlessly,
capture through the addon, land leaves in the scratch witness, sign C2PA
against the surrogate, and grade with `packages/scruple-conformance`.

**Gate:** at least 5 leaves from at least 3 distinct renders. For each: the
artifact exists on disk, its bytes re-hash to the recorded `content_hash`, the
receipt fetches, and the assurance tier is recorded honestly. Print the table.

## WO-B7 — Close out honestly

Write `docs/canon/blender-l2/STATE.md`: what works and is proven by side
effect, what is built but unproven, what needs a human at a Blender GUI, what
needs the founder. Separate "done" from "done against the surrogate" from
"cannot be done without the real CVM".

**Gate:** every claim of "works" names the observable that showed it.
