# WO-4 · HTTP+WS proxy as the provenance gate

**Scope:** Replace browser-side `scruple-canvas-witness.js` + token-in-URL with a server-side HTTP+WS proxy between browser and Modal. The proxy IS the gate: every workflow JSON and every output blob is captured server-side.

**Reference:** `docs/architecture/canvas-v2.md` decision 2.

## New files

- `app/canvas-proxy/[sessionId]/[...path]/route.ts` — Next.js streaming HTTP proxy (GET, POST, PUT, DELETE, OPTIONS)
  - validates session ownership (sessionId → user_id via `canvas_sessions` row)
  - forwards to Modal endpoint URL stored on the session
  - sets `X-Scruple-Shared-Secret` header on outbound
  - intercept rules:
    - POST `/prompt` → tee body, parse `{ prompt: <workflow_api_json> }`, call `lib/canvas/witness.startWorkflow(sessionId, promptId, workflow)` (after response parsed for promptId)
    - GET `/view?filename=...&subfolder=...&type=...` → tee response body, call `lib/canvas/witness.captureOutput(sessionId, filename, bytes, contentType)`
    - everything else → straight passthrough
  - streaming: use `Response(new ReadableStream(...))` with `TransformStream` for body tee

- `scripts/canvas-ws-proxy.mjs` — standalone Node service
  - binds `0.0.0.0:8190`
  - reads sessionId from URL path `/canvas-proxy-ws/<sessionId>/...`
  - validates against DB (open sqlite read-only)
  - opens upstream WS to Modal endpoint's `/ws` with shared-secret header
  - bidirectional pipe; logs frame counts; on `executing` / `execution_success` ComfyUI events → debug log only (HTTP path captures the actual workflow)

- `lib/canvas/witness.ts` — internal API (NOT a Next route)
  - `startWorkflow(sessionId, promptId, workflowApiJson): Promise<void>` — insert `canvas_pending_iterations` row
  - `captureOutput(sessionId, filename, bytes, contentType): Promise<{run_sequence, leaf_hash}>` — call existing `ingestIteration` with workflow + output, witness sign, return

- `systemd/canvas-ws-proxy.service` (or pm2 ecosystem entry) — keeps the Node sidecar alive

## Deletions

- `app/api/canvas/witness/start/route.ts` — replaced by internal lib
- `app/api/canvas/witness/complete/route.ts` — replaced by internal lib
- `custom_nodes/scruple_nodes/js/scruple-canvas-witness.js` — bypassable; superseded
- `components/CanvasBridge.tsx` — drop the `scruple:canvas-witness-{start,complete}` handlers (keep the existing `/api/generate` flow for now; that's the free-tier desktop path through Scruple Studio which is not scruple-web's concern but the file is shared)

## Modifications

- `modal/canvas_app.py` — wrap the `@modal.web_server` decorator's app with an aiohttp middleware that requires `X-Scruple-Shared-Secret == os.environ['SCRUPLE_CANVAS_SHARED_SECRET']`; reject 401 otherwise
- `.env.local` — add `SCRUPLE_CANVAS_SHARED_SECRET=<random>` and create matching Modal secret: `modal secret create scruple-canvas-shared SCRUPLE_CANVAS_SHARED_SECRET=<random>`
- Cloudflare tunnel config — route `wss://canvas-ws.scruple.stooges.ai` → `127.0.0.1:8190` (user-side cf edit; document command in PATCH_NOTES)

## Verify

- `curl -X POST 'http://localhost:3001/canvas-proxy/test-session-id/api/v1/queue'` returns 401 (no valid session)
- With valid session: workflow POST captures → `canvas_pending_iterations` row inserted
- `/view` GET → iteration row inserted with output_hash + leaf
- Modal endpoint directly returns 401 without shared-secret header
- WS sidecar log shows connect + bidirectional frame counts
